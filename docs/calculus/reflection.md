# Reflection

**Status: Characterised**, and deliberately not proved — see below. There is no `Contract.lean`
and there should not be one.

## What it fixes

The document round trip. A document this library writes, read back by the schema it was written
against, is the document — and the guard for that is not a theorem.

## The claim

**A committed document, read back, is the document.** For each of the five document kinds
(`ledger`, `derivation`, `overlay`, `annotation_request`, `narrative`) the JSON Schema is generated
from the pydantic model, the golden fixture is generated by writing that model, and reading the
fixture back yields an equal document.

## The claim was true of one kind out of five when this page first made it

**That is the finding of this tranche, and it is the same shape as the other two in
[the index](./index.md): a page asserting a guard it did not have.** The round trip was tested for
`LedgerGraph` alone — and for three hand-picked fields of it, `nodes`, `edges` and `policy`.
Nothing held the page to "each of the five", and two of the five were not merely untested:

- **`annotation_request` had a generated schema and no committed example at all.** No fixture, so
  nothing read one back and nothing validated the schema against real output. A schema describing
  a shape Python had stopped producing would have kept reporting green on both sides — the Python
  contract test checked the schema was *committed*, and the front-end test's fixture loop covered
  three of the five families and silently ignored the rest.
- **`narrative` was in the fixture and validated by nobody**, on either side.

Both are closed now. `tests/ledger/test_contract.py` holds a five-kind registry to the fixture
sections and fails if a kind has no committed example, and
`test_every_committed_document_reads_back_as_the_document_it_came_from` round-trips **every
document of every kind** — sixteen of them — comparing the re-serialised bytes rather than a few
fields. The front end's `contract.test.ts` validates all five families against the same fixture.

## And round-tripping them found a second thing wrong with the fixture

**The committed fixture was not a document the library produces.** `_pin_timestamps` replaced every
instant with `FIXTURE_INSTANT.isoformat()`, which spells a UTC instant `+00:00`; pydantic spells it
`Z`. Both denote the same moment and both parse, so nothing failed and nobody noticed — but a
fixture's entire claim is that it is what Python actually produced, and this one differed from that
in a character. The pinning helper now preserves the spelling as well as the value, and the
sixteen-document round trip is what caught it: a comparison of three fields would have missed it
forever, and a comparison of *parsed* values would have too.

## Why the guard is a test and not a theorem

A theorem here would be a statement about generated files rather than about a Lean object, and
making it a Lean object would mean porting the pydantic models into Lean — at which point the
theorem is about the port. That is the same failure this section refuses everywhere else: a proof
about a re-implementation, dressed as a proof about the library.

So the layer is **characterised**: the claim describes what the contract does, this repository
cannot violate it without `tests/ledger/test_contract.py` failing first, and it is deliberately not
proved. **A theorem nobody consults dilutes a gate whose value is that every entry in it can be
broken by a change** — and this entry is already broken by a change, every time somebody adds a
field.

## What it is about in the tree

| The claim's subject | The tree |
|---|---|
| one hand-maintained description | `src/chainlens/ledger/schema.py::render_schemas` |
| the five kinds, and which fixture section holds each | `tests/ledger/test_contract.py::REFLECTIONS` |
| the round trip, over every committed document | `test_every_committed_document_reads_back_as_the_document_it_came_from` |
| the fixture | `tests/ledger/fixtures.py` |
| the same fixture, from the other language | `web/src/schema/contract.test.ts` |

The arrangement is worth naming because it is the third of its kind in this repository — a
hand-maintained description, generated artefacts, and a test that fails on a diff. `make contract`
regenerates the wire schema; `make docs-reference` regenerates the API reference;
`make vocabulary` regenerates [the vocabulary table](./vocabulary.md)'s artefacts. Each is a
convenience, and the *guard* is always the test, because a convenience somebody has to remember to
run is not a check.
